# RAG 주제 분류 회귀 수정 — 이슈 #31

브랜치: `fix/#31-rag-topic-routing`. PR #30은 아직 병합 전이므로 최신 main(77e431d)에서
독립적으로 수정했다. 기존 API 응답 형식과 DB 스키마는 유지하며 `policyVersion`은
`evidence-policy-v2`로 변경한다. 운영 서버 자동 재시작/DB 수정/유료 호출은 하지 않았다.

## 문제와 변경

- 기존 `보낸`/`보냈` 단독 탐지가 청첩장·사진·서류 전송도 송금 주제로 판단했다.
  이 단어는 제거하고 돈·금액·현금·보증금·수수료·대금과 송부 동사가 붙는 패턴을 사용한다.
  `송금`, `이체`, `입금`, `지급정지` 같은 명시적인 표현은 유지한다.
- 청첩장/초대장/부고장에 수상함·설치 요구 등 의심 문맥이 같은 문장에 있으면
  스미싱 근거로 연결한다. 단순히 친구가 청첩장을 보냈다는 표현은 명확화 대상으로 남긴다.
- 통신사/휴대폰 문맥 + 청구/과금 + 콘텐츠/결제를 같은 문장에서 확인해 소액결제로 연결한다.
- 유니코드 NFKC와 보이지 않는 format 문자를 정규화하고 `소액 결제`/`계좌 이체`도 인식한다.
- 서로 다른 문장의 단어를 조합하지 않는다. 명시적 다중 피해는 복수 주제로 유지한다.

문맥 조합 규칙이며 문장 이해 모델·학습 기반 라우터·사기 분류기가 아니다. 부정·인용을
완벽히 이해하지 않는다. 예를 들어 '돈은 아직 보내지 않았다'도 송금 관련 문서 질문일 수
있으므로 주제 탐지는 실제 피해 발생 여부 판정으로 해석하면 안 된다.

## 검증과 해석

`topic-routing-v2.jsonl`은 관찰된 실패를 기반으로 작성한 **합성 회귀 사례 28개**다.
실제 분포나 독립 holdout이 아니다. 수정 전/후 JSON은 동일 fixture SHA256을 사용한다.
정확도라고 일반화하지 않고 회귀 기대 주제 집합의 일치 건수로 해석한다.

- 동일 28개 기대 주제 일치: 수정 전 12/28 → 수정 후 28/28.
- 전체 AI 비통합 테스트: 91 passed, DB 통합 6개 제외. Ruff 통과.
- 최초 새 테스트 실행: 21 failed / 12 passed. 실패 재현 후 구현을 수정했다.
- 주제 대비 사례뿐 아니라 실제 근거 family 선택, 복합 피해의 필수 문서 검사,
  RagService 후보 조회→모의 생성→인용 재검증 경로를 테스트했다.
- 기존 문서 신선도·출처·충돌·삭제 검사도 유지한다.
- 신규 독립 데이터에서의 모델 성능이나 생성 답변 정확도 개선을 주장하지 않는다.

```bash
cd ai
.venv/bin/python -m ruff check .
.venv/bin/python -m pytest -m 'not integration' -q
.venv/bin/python scripts/topic_routing_report.py --output .artifacts/topic-routing-v2.json
```

수정 전 재현에는 main 기준 커밋 77e431d의 evidence.py와 동일 fixture/report script를
별도 checkout에서 사용한다. `before.json`은 수정 전 실행 결과, `after.json`은 수정 후 결과다.
CI도 provider/API key/DB 없이 실행한다. DB 통합 테스트는 별도 환경에서 실행해야 한다.
