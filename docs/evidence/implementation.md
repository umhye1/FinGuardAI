# 검토된 근거의 충돌·부족을 통제하는 RAG

관련 이슈: https://github.com/umhye1/FinGuardAI/issues/23

2026-09-11 구현. 과거에 수행한 실험을 복원한 기록이 아니라 이번 변경의 설계·검증 기록이다.

## 처리 흐름

1. 질문의 계좌 송금 / 스미싱 / 휴대폰 소액결제 주제를 규칙으로 찾는다. 식별할 수 없으면 상황을 묻는다. 현재 한국 금융소비자 대상의 세 주제만 지원한다.
2. 완료된 문서 중 주제 메타데이터가 있는 문단을 최대 201개 읽는다. 200개를 초과하면 일부만 보고 결론 내리지 않고 보류한다. 확대 운영에는 페이지 순회·별도 정책 저장소가 필요하다.
3. 임베딩이 있으면 pgvector 코사인 검색 점수와 한국어 부분 문자열 키워드 순위를 RRF(상수 60)로 결합한다. 키워드는 질문 토큰과 주제별 동의 표현을 포함한다. 임베딩이 없으면 키워드 검색만 수행한다. 이는 BM25 구현이 아니다.
4. 공식 지침과 사례를 구분한다. 사례는 답변 지침으로 사용하지 않는다. 승인되지 않은 일반 업로드는 메타데이터가 없어 제외한다.
5. 같은 기관·지침 계열·적용대상 안에서 게시일이 최신인 문서를 선택한다. 다른 기관의 문서는 날짜만으로 덮어쓰지 않는다. 같은 날짜의 서로 다른 절차도 충돌로 보류한다. 최신 문서가 만료·변경되었으면 이전 문서로 자동 후퇴하지 않는다.
6. 검토된 구조화 절차의 `(적용대상, 주제, 판단 항목)`에 서로 다른 값이 있으면 생성 전에 보류한다. 예: 같은 계좌 송금 피해 신고 창구에 상반된 값이 등록된 경우. 서로 다른 업무의 112/118은 충돌이 아니다.
7. 주제별 필수 지침 계열을 확보하고 각 계열의 문단을 검색 결과에 예약한다. 송금=`transfer-response`, 문자·앱=`smishing-response`, 소액결제=`mobile-payment-response`. 필요한 계열을 인용에서 빠뜨려도 보류한다.
8. 생성 후 관련 주제 전체의 ID·내용 해시·메타데이터를 다시 비교한다. 문서 추가·삭제·변경 시 보류한다.
9. Spring은 인용 시점의 원문 해시와 메타데이터 스냅샷을 DB와 대조한다. 미검토·변경 문서의 답변은 저장 시 거부한다. 보류 문구와 추가 질문은 서버가 소유한 문구로 표시한다.
10. 답변에 정책 버전과 보류 사유, 인용에 출처 URL·메타데이터를 저장한다. 화면에서 공식 출처·게시일·요약 여부를 확인할 수 있다.

## 자료 수집·승인 기준

`ai/data/official/manifest.json`은 명시적으로 검토한 소규모 corpus의 입력이다. 게시기관·게시일·수집일·검토일·재검토 기한·적용대상·버전·지침 계열·주제·정규화된 절차·내용 SHA-256을 기록한다.

허용한 공식 기관 호스트의 HTTPS 주소만 등록한다. 웹페이지나 모델이 스스로 metadata를 승인할 수 없고, 일반 문서 업로드도 자동 승인하지 않는다. 새 자료는 원문을 확인하고 필수 조건·예외 및 구조화 절차 값을 검토한 후 manifest에 추가하고 CLI로 등록한다. 현재 검토는 개발 단계의 출처 대조이며 기관의 인증·법률 검토를 뜻하지 않는다. 검토기한은 수집 후 90일의 프로젝트 운영 규칙으로, 법령의 유효기간과 다르다.

문서 버전은 원문 기관이 부여한 버전 번호가 아닌 `게시일-summary-v1` 형식의 프로젝트 스냅샷 버전이다. 공식 원문에서 발행일을 확인하지 못하면 임의 날짜로 승인하지 않는다. 2025년 합동 자료는 첨부파일 이름의 1월 17일과 웹 게시일 1월 20일을 구분해 웹 게시일을 사용했다.

현재 저장한 자료:

| 출처 | 게시일 | corpus 항목 |
| --- | --- | --- |
| [금융위 게시 관계기관 합동 자료(금감원·KISA 공동 참여)](https://www.fsc.go.kr/no010101/83889) | 2025-01-20 | 송금 피해 대응 지침, 카드 배송 사칭 사례 |
| [KISA 카드 배송 사칭 주의 권고](https://spam.kisa.or.kr/spam/na/ntt/selectNttInfo.do?bbsId=1001&mi=1019&nttSn=2642) | 2025-04-01 | 스미싱 대응 지침, 휴대폰 소액결제 피해 절차 |
| [금융위 통합신고·대응센터 안내](https://www.fsc.go.kr/po010101/80830) | 2023-09-26 | 신고 창구 통합 설명 |

금감원 단독 사이트 원문 확보로 표현하지 않는다. 금감원이 참여한 합동 공식 자료를 금융위 사이트에서 확인했다. 선택한 3개 자료에서 실제로 모순된 절차가 발생했다고 주장하지 않는다. 2023년 안내의 과거 창구 설명을 현재 규칙으로 옮기지 않았다.

원문 HTML 3개는 `ai/data/official/raw/`에 로컬 보관하며 Git/Docker에서 제외한다. 공개 저장소에는 출처·원문 SHA-256·수집시각 및 짧은 자체 요약 5개를 저장한다. 요약을 원문 전문으로 표시하지 않는다. 전체 원문을 재배포하려면 기관별 이용조건과 제3자 콘텐츠를 확인해야 한다.

## 등록·검색 실행

저장소 루트에서 다음 명령으로 자료 해시와 스키마를 검증한다. Python 패키지 설치는 기존 `ai/README.md`를 따른다.

```sh
ai/.venv/bin/python -m finguard_ai.corpus --manifest ai/data/official/manifest.json
```

Spring을 새 코드로 시작해 Flyway V7까지 적용한 뒤, AI 서비스의 기존 DB 설정을 사용해 등록한다.

```sh
ai/.venv/bin/python -m finguard_ai.corpus --manifest ai/data/official/manifest.json --apply
```

등록은 원자적이며 같은 ID·내용은 중복 저장하지 않는다. 같은 ID의 내용이나 metadata가 달라지면 거부한다. 새 버전은 새로운 corpus_id로 추가한다. 문서는 한 문단의 검토 단위로 저장한다. 원문 요약 파일은 일반 업로드 디렉터리 밖에 있어 백엔드 문서 삭제가 저장소 원본을 삭제하지 않는다.

임베딩 없이도 등록된 지침으로 키워드 검색이 가능하다. 실제 생성에는 기존 Gemini 설정이 필요하다. 벡터와 키워드 결합을 사용하려면 반환된 document ID 각각을 기존 `finguard-index --document-id ID`로 인덱싱한다. 이 단계와 실제 생성 요청은 외부 API 호출이다.

Docker AI 이미지에도 검토 manifest와 요약이 포함된다. API·Spring을 함께 배포해야 하며 이전 버전 AI의 ANSWERED 응답은 새 Spring에서 정책 스냅샷 누락으로 거절된다. 컨테이너에서는 `/app/data/official/manifest.json`을 사용한다. 기존 일반 업로드는 보존되지만 검토 전까지 새 RAG 답변에 사용하지 않는다.

원문 재수집은 다음 명령으로 가능하다. 다운로드가 원문 변경을 발견해도 자동으로 지침 요약·승인을 갱신하지 않는다.

```sh
ai/.venv/bin/python -m finguard_ai.sources --manifest ai/data/official/manifest.json
```

## 평가와 한계

```sh
ai/.venv/bin/python -m finguard_ai.evaluation \
  --manifest ai/data/official/manifest.json --as-of 2026-09-11 \
  --output docs/evidence/retrieval-evaluation.json
```

이 비교는 같은 문자 n-gram TF-IDF 벡터로 정책 없는 top-2와 하이브리드+정책 적용 결과를 대조한다. 실제 공식 출처 기반 요약을 검색하지만 Gemini 임베딩/생성 성능 평가는 아니다. 원문 출처·버전·해시와 선택된 인용 후보를 기록한다. 벡터 검색만으로도 답할 수 있는 6개 질문의 필수 계열이 모두 검색되었다. 따라서 검색 정확도 향상을 주장하지 않는다. 정책 적용 결과 6개는 답변 가능, 모호/범위 밖 2개는 추가 질문으로 처리되어 8개 기대 동작을 충족했다.

합성 테스트는 실제 지침 metadata를 복사해 반대 값·과거 버전·같은 날짜의 충돌 등을 주입한다. 이 값들은 공식 manifest에 넣지 않는다. 실제 기관 자료가 모순됐다는 증거가 아니라 오류 상황을 만들어 차단 여부를 검증한 것이다.

구조화한 절차에 없는 모순, 질문의 부정·복잡한 맥락, 요약에서 누락한 조건, 인용 문단과 답변의 의미적 불일치는 완전히 검증하지 못한다. LLM에도 모순·불확실성을 보류하도록 지시하지만 이를 독립된 의미 검증기로 주장하지 않는다. 새 주제/관할/적용대상은 별도 검토가 필요하다. 검토한 corpus 범위의 최신 자료 우선이며 인터넷 전체의 최신 지침을 보장하지 않는다.
