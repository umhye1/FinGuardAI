# AI 성능 개선 실험 1차 기록 (2026-09-29)

이번 단계는 유료 API 호출 없이 재실행할 수 있는 실험 기반 구축이다. 실제 서버의 OpenAI
분류 경로나 운영 임계값을 변경하지 않았다. 한국어 사전학습 모델/생성 LLM의 파인튜닝도
아니다. 새 후보는 **3개 의도 라벨을 학습한 문자·단어 n-gram 로지스틱 회귀**다.

## 실행

저장소 루트에서 실행한다. 설치는 `ai/README.md`의 잠금 의존성 설치 방법을 따른다.

```bash
cd ai
.venv/bin/python -m finguard_ai.context_benchmark \
  --data data/benchmarks/context-v1 --output-dir .artifacts/context-v1 --allow-synthetic
.venv/bin/python -m finguard_ai.rag_benchmark \
  --data data/benchmarks/rag-v1 --corpus data/official --output-dir .artifacts/rag-v1
.venv/bin/python -m pytest -m 'not integration' -q
```

두 CLI는 `.env`/API 키/DB를 읽지 않고 외부 API를 호출하지 않는다. 학습 모델은 무시되는
`.artifacts/`에 JSON으로 저장한다. 결과 JSON에는 데이터 해시와 버전, 사례별 예측,
지표의 분자·분모를 남긴다. 출력 디렉터리는 실험마다 다르게 지정해 이전 결과를 보존한다.

## 분류 실험

84개 직접 작성한 합성 문장(train 36/dev 18/test 30). test는 클래스별 10개다.
같은 시나리오의 사기/예방/정상 문장은 같은 split에 둔다. 파일 해시, ID, 정규화 텍스트,
group 교차를 검증한다. 독립 검수·실제 분포·의미적 중복 검증은 아직 없다.

| 비교 방식 | 사기 미탐(보류 포함)/10 | 사기를 PASS/10 | 예방 오탐/10 | 보류/30 |
|---|---:|---:|---:|---:|
| 규칙 스냅샷, 40점 이상 FLAG | 3 | 3 | 6 | 0 |
| 기존 이진 학습 방식, .25/.75 | 10 | 0 | 0 | 30 |
| 이진 방식, dev 임계값 조정 .49/.51 | 1 | 0 | 0 | 1 |
| 3분류 문자 n-gram | 0 | 0 | 0 | 1 |
| 3분류 문자+단어 n-gram 후보 | 0 | 0 | 0 | 0 |

기존 이진 방식은 배포된 모델 파일 그대로가 아니라, 동일 train 데이터에서 PREVENTION을
NORMAL로 합쳐 기존 학습 알고리즘을 재학습한 통제 비교다. 규칙은 당시 로컬 14개
키워드의 명시적 스냅샷이며 사용자가 이후 변경한 DB를 자동 반영하지 않는다. 40점 이진화는
평가를 위한 SUSPICIOUS 이상 매핑이며 실제 8단계 위험도/사기 확률과 다르다.

첫 실험을 살펴보니 이진 모델도 보류를 무시하고 0.5로 나누면 사기/예방을 모두 구분했다.
그래서 **첫 결과 확인 후 임계값만 조정하는 비교군을 추가**했다. 조정 값은 dev에서만
선택했지만, 이 추가 분석은 완전히 사전 등록된 실험으로 주장하면 안 된다. 3분류 후보의
특징/가중치/C/임계값을 test 결과에 맞춰 변경하지는 않았다. 후보의 선택 기준과 모든
개발셋 trial은 JSON에 있다. 이진 모델과 후보의 비용·표현력·임계값 변화가 모두 섞이므로
후보가 일반적으로 더 우수하다는 결론은 아직 불가능하다.

3분류 두 후보의 강제 argmax 혼동행렬은 test에서 각 클래스 10/10이었다. 이처럼 쉬운
소규모 합성 데이터의 만점은 실제 성능 증거가 약하다. 이진 임계값 조정만으로도 보류가
대부분 해소됐고, 문자+단어 후보는 문자 후보보다 느렸다(실행별 p50/p95는 JSON 참조).
현 단계 핵심 결과는 '고성능 모델 완성'보다 **오탐·보류·임계값 효과를 구분할 평가 체계**다.

## RAG 검색과 생성 평가

공식 출처를 검토해 저장한 요약 6개(전체 PDF 아님), 직접 작성한 질문 20개,
정답 문서가 있는 15개에 대해 exact corpus ID 기준 Recall@2/MRR@2를 계산했다.
복합 질문은 필요한 두 문서를 모두 찾았는지 별도로 평가한다. 정답 문서가 없는 5개를
검색 성공률의 분모에 넣어 점수를 부풀리지 않는다.

| 방법 | 평균 Recall@2 | 모든 필수 문서 검색 | MRR@2 |
|---|---:|---:|---:|
| 로컬 TF-IDF 벡터 | 0.767 | 11/15 | 0.667 |
| 기존 어휘+벡터 RRF | 0.900 | 13/15 | 0.667 |
| 기존 근거 정책 선택 이후 | 0.800 | 12/15 | 0.800 |

이 표는 **기존 검색 방식의 실패를 새 평가셋으로 측정한 것**이다. 이번에 운영 검색 알고리즘을
개선·배포했다는 의미가 아니다. provider embedding과 생성 LLM은 호출하지 않았다.
정책 선택은 top-k 후보만 재정렬하는 방식이 아니라 전체 검토 문서를 읽으므로 벡터/하이브리드
검색 품질과 구별해야 한다. 정책이 답변 생성 가능으로 판단했는지와 정답 문서 포함 여부도
따로 남겼다. 인용이 있다는 사실로 생성 답변의 정확도를 평가하지 않는다.

발견한 실패:

- `지인이 보낸 모바일 청첩장…`에서 `보낸`이라는 단어 때문에 송금 주제로 잘못 연결됨.
- `통신사 청구서…콘텐츠 비용`은 검색에서 정답이 나와도 정책 주제 탐지가 놓침.
- `보이스피싱 통합신고 센터` 질문은 적절한 문서를 찾아도 정책이 명확화 요청을 반환함.
- `송금한 돈이 내일 전액 반환된다는 근거` 요청에 대해 자료가 충분한지 더 세밀한 검토 필요.
  이 질문은 '근거 없음'이라고 답하는 것도 타당할 수 있어 라벨 독립 검수 대상으로 남긴다.

이제 이 질문들은 관찰된 회귀 사례다. 이를 수정한 뒤 동일 질문에서 오른 점수만으로 일반화
개선을 주장하지 않고, 새로운 독립 holdout 질문을 먼저 확보해야 한다.

생성 답변의 근거 충실도는 **미측정(null)**. `.artifacts/rag-v1/faithfulness-review.template.json`
에는 질문과 해시가 고정된 원문, 빈 검수 칸이 있다. 실제 생성 답변을 확보한 후 복사본에
아래 항목을 채워 `--review 경로`로 재실행한다. 답변을 새로 생성하는 기능이 아니다.

```json
{
  "questionId": "transfer-stop",
  "answer": "실제 생성 답변 전문",
  "modelVersion": "실제 모델·프롬프트 버전",
  "reviewer": "검수자 식별자",
  "allClaimsReviewed": true,
  "claims": [{
    "text": "답변에 실제 포함된 하나의 사실 주장",
    "verdict": "SUPPORTED",
    "rationale": "원문이 이 주장을 뒷받침하는 이유",
    "citations": [{"corpusId": "joint-transfer-2025", "sha256": "원문 해시", "quote": "원문의 정확한 발췌"}]
  }]
}
```

verdict: SUPPORTED / UNSUPPORTED / CONTRADICTED. 인용 ID·해시·발췌의 존재는 도구가 검증하고,
**의미상 뒷받침하는지와 모든 주장을 나눴는지는 사람이 판단**한다. 검수하지 않은 답변은
분모에서 제외하고 pending 수를 함께 표시한다. 자동 NLI 평가나 독립 평가자 검수 완료로
포장하면 안 된다. 근거 충실도는 답변의 완전성/업무상 정확성과도 다른 지표다.

## 다음 개발 순서 / 자소서 소재의 경계

1. 별도 검수자로 라벨·시나리오 중복을 검토하고, 사용 권한 있는 실제 사례와 어려운 독립
   test를 확보한다. 이번 test를 보면서 조정하는 작업은 개발/회귀 검증으로만 기록한다.
2. 단순 임계값 조정 기준선을 유지한 채 한국어 사전학습 encoder 분류기를 미세조정해
   정확도·사기 미탐·예방 오탐·보류·CPU 지연을 비교한다. 데이터 확보 전 대형 모델부터
   붙이거나 현재 n-gram 모델을 'LLM 파인튜닝'으로 부르지 않는다.
3. RAG 주제 라우팅의 단어 중복/우회 표현을 개선하고 신규 holdout에서 검증한다. 검색 실패와
   정책 실패를 구분해 수정한다. 후보 모델·검색기는 검증 전 운영에 자동 승격하지 않는다.
4. 유료 생성은 추후 요청 시 소량만 실행하고 위 검수 양식으로 근거 충실도와 미지원 주장을
   측정한다. 그 후 분석 의도+피해 상황 기반 대응 초안 기능에 연결한다.

현재 사용할 수 있는 설명: “예방 문구 오탐을 재현하고 3종 문맥 데이터와 누수 검사를 만들었다.
모델 변경뿐 아니라 임계값만 조정하는 비교군을 둬 오탐 감소와 판단 보류를 분리해 검증했다.
RAG는 검색·정책·생성 오류를 나눠 평가할 수 있도록 구현했다.”
실제 금융사기 탐지 성능 개선율, 실사용자 검증, LLM 파인튜닝 경험은 아직 주장하지 않는다.
